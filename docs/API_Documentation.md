# Employee Management & Attendance System API Documentation

## 1. Project Overview

The **Employee Management & Attendance System** is a RESTful backend application developed using Spring Boot.

The system provides APIs for:

- JWT-based authentication
- Employee management
- Department management
- Designation management
- Attendance tracking
- Leave management
- Employee search and filtering
- Pagination and sorting
- Role-based access control

### Technology Stack

- Java 17
- Spring Boot
- Spring Security
- JWT Authentication
- Spring Data JPA
- Hibernate
- MySQL
- Maven
- Swagger / OpenAPI
- Postman

---

# 3. Authentication

The application uses **JWT Bearer Token authentication**.

Users must first authenticate through the login endpoint.

## Login

```http
POST /auth/login
```

### Authentication

No authentication required.

### Request Body

```json
{
  "email": "your-email@example.com",
  "password": "your-password"
}
```

### Response

The API returns a login response containing the authentication information generated by the application.

Copy the JWT token from the response.

For protected endpoints, send the token using:

```http
Authorization: Bearer <JWT_TOKEN>
```

### Important

Do not commit real passwords, JWT secrets, database passwords, or other sensitive credentials to GitHub.

---

# 4. Roles

The application supports role-based authorization.

The roles used by the controllers are:

- `ADMIN`
- `MANAGER`
- `EMPLOYEE`

Access to specific operations is controlled using Spring Security and `@PreAuthorize`.

# 7. Employee Pagination and Sorting

## Get Employees with Pagination

```http
GET /employees/page
```

### Access

Authenticated user.

### Query Parameters

| Parameter | Type | Description |
|---|---|---|
| `page` | int | Page number |
| `size` | int | Number of records per page |
| `sortBy` | String | Employee field used for sorting |

### Example

```http
GET /employees/page?page=0&size=5&sortBy=name
```

The API sorts the requested field in **descending order**.

### Success Response

```text
200 OK
```

Returns a Spring Data `Page<EmployeeDTO>` containing:

- Employee records
- Page information
- Total number of records
- Total number of pages
- Current page information

# 12. HTTP Status Codes

The application uses standard HTTP response codes.

| Status Code | Meaning |
|---|---|
| `200 OK` | Request completed successfully |
| `201 Created` | Resource successfully created |
| `204 No Content` | Resource successfully deleted |
| `400 Bad Request` | Invalid request or validation failure |
| `401 Unauthorized` | Authentication is missing or invalid |
| `403 Forbidden` | Authenticated user does not have permission |
| `404 Not Found` | Requested resource does not exist |
| `409 Conflict` | Request conflicts with existing data or business rules |

The exact error response depends on the exception and validation handled by the application.

# 13. JWT Authorization Workflow

The normal request flow is:

```text
1. User sends login credentials
        ↓
2. POST /auth/login
        ↓
3. Server validates credentials
        ↓
4. JWT token is generated
        ↓
5. Client sends JWT with protected requests
        ↓
6. Spring Security validates the JWT
        ↓
7. Role-based authorization is applied
        ↓
8. Request is processed
```

For protected endpoints, include:

```http
Authorization: Bearer <JWT_TOKEN>
```

2. Copy the JWT token from the response.
3. Click **Authorize** in Swagger.
4. Enter the token using the configured Bearer authentication scheme.
5. Execute protected endpoints.

# 18. Security Notes

The following security practices are implemented in the project:

- JWT-based authentication
- BCrypt password hashing
- Role-based authorization
- Protected API endpoints
- Environment-variable based database password configuration
- Environment-variable based JWT secret configuration
- Validation on applicable request bodies
- Centralized exception handling

Sensitive credentials should never be committed to the repository.
